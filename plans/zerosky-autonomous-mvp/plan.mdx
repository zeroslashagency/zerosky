## 🎯 MVP Definition (What We're Building)

### Core User Flows

```diagram
type: sequence
participants:
  - name: Cashier
  - name: POS App
  - name: Kitchen Display
  - name: Printer

Cashier -> POS App: Login (PIN)
POS App -> Cashier: Dashboard

Cashier -> POS App: Select table
Cashier -> POS App: Browse menu
Cashier -> POS App: Add items to cart
Cashier -> POS App: Apply modifiers

Cashier -> POS App: Send to kitchen
POS App -> Kitchen Display: KOT (Kitchen Order Ticket)
POS App -> Printer: Print KOT

Kitchen Display -> Kitchen Display: Mark items ready

Cashier -> POS App: Generate bill
POS App -> Cashier: Bill with GST breakdown

Cashier -> POS App: Accept payment (Cash/Card/UPI)
POS App -> Printer: Print receipt
POS App -> Cashier: Order complete
```

- ✅ Email + password login

- ✅ JWT access + refresh tokens
- ✅ Redis session management

**Menu Management:**
- ✅ Categories (starters, mains, desserts, drinks)

- ✅ Search & filter

- ✅ Table selection

- ✅ Item notes (e.g., "no onions")
- ✅ Order status tracking (PENDING → CONFIRMED → PREPARING → READY → SERVED)

**Kitchen Operations:**
- ✅ KOT generation with order details
- ✅ Print to thermal printer (58mm/80mm)
- ✅ Kitchen display view
- ✅ Mark items as prepared
- ✅ Priority/rush orders

**Billing & GST:**

## ✅ Quality Standards

### Code Quality

- **TypeScript Strict Mode:** All code must pass `strict: true`
- **No `any` types:** Use proper type definitions
- **No TODO/FIXME:** Complete implementation only
- **No dead code:** Remove unused imports/variables
- **Consistent formatting:** Prettier with project config

### Test Coverage

- **Minimum 80% coverage** per package
- **Unit tests:** All business logic functions
- **Integration tests:** API endpoints and database operations
- **E2E tests:** Critical user flows (login → order → payment)
- **No skipped tests:** Fix or remove, don't skip

### Security

- **JWT tokens:** Secure storage (httpOnly cookies preferred)
- **Password hashing:** bcrypt with 12 rounds (already implemented)
- **SQL injection:** Prisma parameterized queries (already safe)
- **XSS protection:** React auto-escaping + CSP headers
- **CORS:** Proper origin whitelist
- **Rate limiting:** Implemented in API layer

### Performance

- **First Load:** < 3 seconds
- **API Response:** < 500ms (p95)
- **Bundle Size:** < 300kb (main bundle)
- **Database Queries:** N+1 prevention, use `include` wisely

### Accessibility

- **Keyboard Navigation:** All interactive elements accessible
- **ARIA Labels:** Proper labeling for screen readers
- **Color Contrast:** WCAG AA minimum (4.5:1)
- **Focus Indicators:** Visible focus states

## 🚨 Risk Mitigation

### Technical Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| **Database connection issues** | High | SSH tunnel health check, auto-reconnect, fallback to SQLite offline mode |
| **Test flakiness** | Medium | Run tests 2-3x in CI, fix non-deterministic tests, seed data properly |
| **Razorpay integration complexity** | Medium | Skip Zomato/Swiggy integration, use Razorpay test mode, comprehensive error handling |
| **Print driver compatibility** | Medium | Support both 58mm and 80mm, fallback to PDF export, ESC/POS standard compliance |
| **Type errors after merge** | Low | Already resolved via Prisma regeneration, strict TypeScript prevents future issues |

### Process Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| **Agent coordination issues** | High | Clear ownership, daily sync, explicit handoff protocol |
| **Scope creep** | Medium | Strict MVP definition, defer non-essential features, "no" is okay |
| **Fact-checking failures** | High | Dual-agent verification, no self-approval, evidence-based claims only |
| **Timeline slippage** | Medium | Buffer time built-in, parallel work streams, daily progress tracking |
